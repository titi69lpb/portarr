# Portarr i18n (FR/EN) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Portarr fully FR/EN with personal, instance-default and first-run-setup language choice, matching plexcrew-portal's options.

**Architecture:** Port plexcrew-portal's i18n (`src/lib/i18n/*`, dictionaries, `t()`) into Portarr, adapting identity from `plex_id` to Portarr's `(provider, external_id)` users and `SessionUser {provider,userId}`. Locale = personal `users.locale` > `settings.default_locale` > browser Accept-Language (new installs only) > FR.

**Tech Stack:** Next.js (app router), better-sqlite3, vitest, TypeScript.

**Spec:** `docs/superpowers/specs/2026-09-24-portarr-i18n-design.md`

**Reference source (read-only, do NOT edit):** the private reference implementation (private plexcrew-portal, has the finished French/English implementation). Portarr working tree: the repository root.

## Global Constraints
- Locales: exactly `fr` and `en`; `DEFAULT_LOCALE = 'fr'`; missing EN key falls back to FR.
- Existing installs with no `default_locale` and no Accept-Language rule trigger keep FR.
- Public repo: NO private data (no `example-domain`, real IPs, keys, usernames); keep Tailwind `plexcrew-*` tokens.
- No emojis, no em-dashes in new user-facing copy.
- Every task ends green: `npm test`, `npm run typecheck`, `npm run build` (build only from Task 3 on and at the end).
- Commit per task, message style `feat(i18n): ...`; do not push, do not tag (controller does release).
- Verify Portarr APIs by reading its code before use; do not assume plexcrew signatures (identity differs).
